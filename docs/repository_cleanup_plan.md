# 仓库整理建议

本清单用于下一阶段讨论，尚未执行目录迁移或删除。当前工作树已有未提交的代码和文档改动，整理前应明确它们的归属。

1. **确认基线**：查看 `git status`、开发改动和 `tests/`；将几何门槛、统一工作流、前端的变更按功能分组，并记录对应运行证据。
2. **区分代码与样例**：`backend/` 放服务逻辑，`frontend/` 放界面，`integrations/` 按 L1、CRM、演示飞机等流程存适配脚本；检查样例文件和诊断日志是否应另设 `fixtures/` 或保留在 `data/`。
3. **统一配置**：把 `config.json` 中的个人绝对路径改为可复制的示例配置与本机配置。
4. **整理运行产物**：检查根目录 `ANSA_Input.log` 等生成文件是否应由 `.gitignore` 覆盖；保留必要的可复现样例和验收说明，不直接删除现有数据。
5. **收敛文档**：维持中文 README 和文档索引；把随开发变化的状态写到现状页，日期型实验记录保留为历史证据，并逐步翻译仍需长期维护的英文页。
6. **验证后迁移**：先运行现有单元测试和前端构建，再逐项移动文件、修正路径引用，最后对 L1 与通用人工流程做针对性回归。
